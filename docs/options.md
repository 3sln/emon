# Options, limits and errors

Every host takes what a conversion should do in the same words. This page lists them all. The tables are
generated by `bb docs` from `api/surface.edn` (the frozen option keys, limits and HTML words) and from the
defaults in `kin/config.kin`, so they cannot drift from the code: `bb docs --check` is part of the fast core.

## The `key=value` text

One text says what a conversion is asked to do. Each line is `KEY=VALUE`, split at the first `=`; lines are
separated by a line feed; an empty line is nothing; the last line that sets a key wins, except `limit.NAME` and
`producer.NAME`, which are lists. An unknown key, a value out of range or a word that is not in the list is
refused with a sentence. The text is parsed by the engine itself, the same code in every host.

| Host | How the text gets in |
|---|---|
| CLI | `key=value` arguments of `emon convert`, and the flags that spell the common ones ([docs/cli.md](cli.md)) |
| Rust | `emon::parse_options(text)` gives `Parsed { options, config, .. }`; or fill `Options` and `Config` by hand ([docs/hosts/rust.md](hosts/rust.md)) |
| Go | `emon.ParseOptions(text)`, or `emon.DefaultOptions()` and `emon.DefaultConfig()` ([docs/hosts/go.md](hosts/go.md)) |
| Java | `Options.parse(text)`, or `Options.defaults()` and `Options.Config.defaults()` ([docs/hosts/java.md](hosts/java.md)) |
| C# | `Options.Parse(text)`, or `Options.Defaults()` and `Options.Config.Defaults()` ([docs/hosts/csharp.md](hosts/csharp.md)) |
| JavaScript | an options object with the same names in camelCase (`assetDpi`, `ocrScope`, `limits: { pages: 50 }`); there is no `parallel` ([docs/hosts/js.md](hosts/js.md)) |
| C | the `options` argument of every call, the text with LF between lines ([docs/hosts/c.md](hosts/c.md)) |
| babashka pod | the second argument of `emon/convert` ([docs/hosts/pod.md](hosts/pod.md)) |

## Options

Defaults are what a conversion does when the text is empty.

<!-- bb docs:begin options-table -->
| Key | Value | Default | Meaning |
|---|---|---|---|
| `asset-bytes` | integer 0..2147483647 | `4194304` | Most encoded bytes one asset may have (the default is 4 MiB). |
| `asset-dpi` | integer 1..2147483647 | `150` | Resolution of the renders cropped for `assets=figures`. |
| `asset-pixels` | integer 0..2147483647 | `4194304` | Most pixels one asset may have (the default is 2048 x 2048). |
| `asset-signatures` | `on`, `off` | `off` | `on` keeps the pixels of handwritten signatures and initials as assets; `off` leaves them out. |
| `assets` | `figures`, `images`, `none` | `none` | Pixels for figures, seals and signatures. `none`: no pixels. `images`: a figure or seal that is one embedded image gets it. `figures`: also the others, cropped from a render (needs a renderer). |
| `assets-bytes` | integer 0..2147483647 | `33554432` | Most encoded bytes all the assets of a document may have (the default is 32 MiB). |
| `chunk` | integer 1..2147483647 | `65536` | Chunk size, in bytes, of the cache the engine reads a byte source through (it reads a source in aligned chunks, only the ones it touches). |
| `fetch-rounds` | integer 0..2147483647 | `24` | Most rounds of range reads a unit may take on a source that answers asynchronously (a browser Blob, a URL). Reaching it is the error `fetch-rounds`. |
| `furniture` | `drop`, `keep`, `policy` | `policy` | What to do with running headers, footers and page numbers. `policy`: drop what the output already says and keep the rest as asides. `keep`: leave all of it in the flow. `drop`: take all of it out (the ledger says what). |
| `js-ocr` | `1` or `0` | `0` | A binding switch, not for the native hosts: the caller owes the `ocr` requests and answers them itself (the browser SDK and the C session API). |
| `js-render` | `1` or `0` | `0` | The same for `render` and `crop` requests (the browser's pdfium, the C session API). |
| `keep-evidence` | `1` or `0` | `0` | Keep the text layer's evidence dump, `Model.evidence()`: a debugging aid. |
| `limit.NAME` | `limit.NAME=N` | none | `limit.NAME=N` sets a named limit for this conversion (`limit.pages=50`); see the limits below. May be given for several names. |
| `locale` | text | none | A BCP 47 language hint (`en`, `de`, `fr-CA`), written to the Model's `settings.locale`. It decides how a drop cap joins its first word when the letter could be a word of its own. |
| `max-rounds` | integer 0..2147483647 | `5` | Most plan/fulfil rounds one page unit may take (the engine asks the ports for renders and OCR in rounds). |
| `ocr` | `always`, `auto`, `never` | `always` | When pages are read with OCR. `always`: every page, born-digital ones too (the text layer and the reading are fused). `auto`: only a page whose text layer is unhealthy, that carries images, or that hides text. `never`: no OCR. With no renderer or no OCR engine configured a request is answered `unsupported` and the text layer stands alone. |
| `ocr-scope` | `witness`, `full` | `full` | What `ocr=always` reads of a born-digital page. `full`: the whole render, text included. `witness`: the render without its text plus a few witness lines of each font (a fraction of the OCR time; a font whose witnesses disagree with its text escalates the page to `full`). |
| `parallel` | integer 1..2147483647 | `1` | How many workers one conversion may spread its fulfilment over. 1 is serial. The limit `workers` caps it. The Model is byte-identical at any N. |
| `producer.NAME` | `producer.NAME=VALUE` | none | `producer.NAME=VALUE` is written into a recorded transcript to say what produced it. The engine does not read it. |
| `record` | `1` or `0` | `0` | Keep a transcript of the conversion's port answers, so it can be replayed without the ports. A session option: the one-shot calls of the C library refuse it. |
<!-- bb docs:end options-table -->

A password is not an option. It travels with its input, and it is never written to a Model, an evidence dump or
a transcript.

## Limits

Every bound on hostile input has a name, a default and a range. Set one for a conversion with
`limit.NAME=N`, or, in the native hosts, for the process with the environment variable `EMON_LIMIT_` followed by
the name in capitals with `_` for `-` (`EMON_LIMIT_PAGES=50`). An option beats the environment, which beats the
default. The range is in the table; a limit has no "unlimited" value (raise it instead), and only `stage-ms` is
off at 0.

<!-- bb docs:begin limits-table -->
| Limit | Default | Range | At the bound | Meaning |
|---|---|---|---|---|
| `limit.asset-placements` | `4096` | 0..2147483647 | the work stops there, the conversion goes on | Image placements considered for assets; later ones are dropped. |
| `limit.fonts-per-doc` | `512` | 0..512 | the work stops there, the conversion goes on | Fonts tracked in a document (at most 512); a font past it has no evidence id and its page is flagged. |
| `limit.form-depth` | `32` | 0..32 | the work stops there, the conversion goes on | How deep form XObjects nest (at most 32); a deeper form is skipped, with a warning. |
| `limit.input-bytes` | `1073741824` | 0..2147483647 | error `input-bytes` | Size of one input, in bytes. |
| `limit.note-bodies` | `4096` | 0..2147483647 | the work stops there, the conversion goes on | Footnote and endnote bodies kept; later ones are dropped. |
| `limit.note-refs` | `8192` | 0..2147483647 | the work stops there, the conversion goes on | Note references followed; later ones are dropped. |
| `limit.objects` | `10000000` | 0..2147483647 | error `objects` | PDF objects in one file. |
| `limit.ocr-requests` | `100000` | 0..2147483647 | error `ocr-requests` | OCR requests in one conversion. |
| `limit.operators` | `50000000` | 0..2147483647 | error `operators` | Content-stream operators run for a document. |
| `limit.pages` | `100000` | 0..2147483647 | error `pages` | Pages in a document. |
| `limit.pattern-depth` | `8` | 0..2147483647 | named, nothing reads it yet | Named for a later feature; nothing reads it yet. |
| `limit.pixels` | `268435456` | 0..2147483647 | error `pixels` | Pixels of one decoded image or rendered page; also bounds what a renderer may draw. |
| `limit.ref-depth` | `64` | 0..2147483647 | the work stops there, the conversion goes on | How deep a chain of indirect references is followed; a deeper one reads as absent. |
| `limit.stage-ms` | `0` | 0..2147483647 | error `stage-ms` | Milliseconds one unit of the plan loop may run; 0 is off. |
| `limit.stream-bytes` | `268435456` | 0..2147483647 | error `stream-bytes` | Decoded size of one PDF stream. |
| `limit.total-bytes` | `1073741824` | 0..2147483647 | error `total-bytes` | Decoded bytes of all the streams of a document. |
| `limit.workers` | `16` | 0..2147483647 | the work stops there, the conversion goes on | Most workers `parallel=N` may use; a larger N is served with this many. |
<!-- bb docs:end limits-table -->

Reaching a bound is, depending on the limit, one of two things. A **breach** ends the conversion with the
named error `NAME` (see below), carrying the limit and the value reached. A **budget** only stops that piece
of work: a reference that is too deep reads as absent, a form nested too deep is skipped with a warning, a
footnote past the limit is dropped, and the conversion goes on, because failing a long book for its 4097th
footnote would be worse than dropping it.

## Errors

A failed conversion has a **name** that does not change between releases and hosts: route on that, not on
the sentence. The C library groups the names in numbered categories; the other hosts have the same names under
their own types (an enum or a variant in Rust, Go, Java and C#, `error.code` in JavaScript, `ex-data` in the pod).

<!-- bb docs:begin errors-table -->
| Category | Code | Name to route on | Meaning |
|---|---|---|---|
| `EMON_ERR_USAGE` | 1 | `usage` | A bad argument or option text. |
| `EMON_ERR_NO_INPUT` | 2 | `no-input` | Nothing was given to convert. |
| `EMON_ERR_LIMIT` | 3 | the limit's name: `input-bytes`, `pages`, `objects`, `pixels`, `fetch-rounds`, ... | A named limit was reached; the error carries the limit and the value reached. |
| `EMON_ERR_PASSWORD_REQUIRED` | 4 | `password-required` | The PDF is encrypted and no password was given. |
| `EMON_ERR_PASSWORD_INCORRECT` | 5 | `password-incorrect` | The password does not open the PDF. |
| `EMON_ERR_ENCRYPTION_UNSUPPORTED` | 6 | `encryption-unsupported` | A security handler emon does not read. |
| `EMON_ERR_UNSUPPORTED_FORMAT` | 7 | `unsupported-format` | Not a PDF, PNG, JPEG or TIFF. |
| `EMON_ERR_DAMAGED` | 8 | a PDF status: `no-startxref`, `bad-xref`, `no-root`, `no-pages`, ...; for an image `undecodable` or `unsupported-image` | A PDF emon could not open, or an image it could not decode. |
| `EMON_ERR_SOURCE_CHANGED` | 9 | `source-changed` | The byte source gave fewer bytes than its length said (or, for a URL, changed under the read). |
| `EMON_ERR_IO` | 10 | `io` | The byte source's read failed. |
| `EMON_ERR_UNSUPPORTED` | 11 | `unsupported` | Specified, not implemented. |
| `EMON_ERR_PLAN` | 12 | `transcript-miss`, a bad transcript, ... | The plan/fulfil loop's own errors, met in replays and with custom ports. |
| `EMON_ERR_INTERNAL` | 13 | `internal` | A bug: the Model failed its own check or the engine panicked. Never the document's fault; please report it. |
<!-- bb docs:end errors-table -->

## HTML words

`--html=` on the drivers, the `html_options` of the C library and the `:html` entry of the pod spec take a
comma list of these words. In the language hosts they are the fields of the HTML options (`HtmlOptions` in Rust
and Go, `Options.Html` in Java and C#, `HtmlOptions` in JavaScript). The default is clean HTML: no ids, no
geometry, policy furniture, milestones on.

<!-- bb docs:begin html-options-table -->
| Word | Effect |
|---|---|
| `align-style` | Also write `style="text-align:…"` and `dir="auto"` next to `data-emon-align`. |
| `assets=external` | `<img src>` is `prefix=` plus the asset's file name; the caller writes the files. |
| `assets=inline` | Assets as `data:` URIs in `<img src>` (the default). |
| `assets=omit` | Figures as if no asset existed. |
| `confidence=N` | `data-emon-conf` on every node whose confidence is below N (0..1000). |
| `drop-furniture` | Leave out the running headers and footers kept as asides. |
| `geometry` | `data-emon-at` (the regions) on nodes, and `data-emon-col="page:band:col"` on blocks. |
| `ids` | `id="emon-N"` on every node. |
| `initials-plain` | Write a drop cap as the bare text, without its `<span data-emon="initial">`. |
| `ledger` | The dropped items, as inert `<template data-emon="dropped">` elements. |
| `no-milestones` | Leave out the empty page-milestone `<span>`s. |
| `prefix=TEXT` | The prefix for `assets=external` (default: none). |
| `pretty` | Indented, one element to a line. |
<!-- bb docs:end html-options-table -->

| Format | What it is |
|---|---|

| `html` | The Model as semantic HTML. |
